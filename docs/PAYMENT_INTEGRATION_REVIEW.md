# 살롱챗 실결제 연동 검토

확인일: 2026-10-18 (한국시간). 비즈사주 코드와 OCI 운영 환경을 읽기 전용으로 확인했다. 운영 결제·계약·키·채널은 변경하지 않았다.

## 확인한 기존 구성

비즈사주는 PortOne V2를 통해 KG이니시스 신모듈(`INICIS_V2`)의 LIVE 카드 결제를 사용한다. OCI 환경에서 Store ID, LIVE 채널 키, API Secret, LIVE 웹훅 Secret이 설정되어 있고 LIVE 활성화 플래그가 켜져 있다. 값 자체는 이 문서에 기록하지 않는다.

참고 코드:
- `창업사주/lib/portone.ts`: 주문 식별자·채널 설정·PortOne 결제 조회 및 금액/상태/상점/채널/상품명/통화 검증
- `창업사주/components/BizSajuApp.tsx`: `@portone/browser-sdk/v2`의 `requestPayment`, PC 결제창 및 모바일 복귀
- `창업사주/app/api/payments/order/route.ts`: 서버 주문 생성과 주문 조건 보관
- `창업사주/app/api/payments/complete/route.ts`: 브라우저 복귀 후 서버 재검증
- `창업사주/app/api/payments/webhook/route.ts`: 원문 웹훅 서명 검증, 결제 재조회, 승인/취소 이벤트 처리
- `창업사주/lib/payment-reconciliation.ts`: 결제 후 결과 미제공 등을 재조회하여 복구

리포트 제공 권한 코드를 그대로 붙이는 것이 아니라, 같은 검증 패턴을 살롱챗의 Express 및 SQLite 재화 원장에 맞게 옮겨야 한다.

## 계약과 심사

기존 비즈사주 MID가 살롱챗의 AI 대화용 하트 충전 상품과 새 URL까지 승인받았는지는 코드나 환경 변수로 확인할 수 없다. 계약·승인 내역은 별도 확인 대상이다.

포트원 공식 서비스 추가 안내는 기존 심사와 다른 업종·품목의 서비스에 추가 심사 및 MID 추가 발급이 필요하다고 안내한다. KG이니시스의 상점아이디 추가 신청은 KG이니시스 상점관리자에서 진행한다. 따라서 **살롱챗용 서비스 추가 심사 및 MID/채널 분리**를 기본 경로로 잡는다. 비즈사주 LIVE 키/채널을 무단 복사해 먼저 실결제를 열지 않는다.

하트 충전은 리포트 단건 판매와 상품 구조가 다르다. 현금화·타인 양도 가능 여부, 사용처, 사용/제공 기간, 무료 보너스, 부분 사용 후 환불 기준, 실제 콘텐츠 범위 등을 사실대로 설명하고 적용 조건을 확인해야 한다. 이름만 이용권으로 바꿔 실제 충전 구조를 숨기는 방식은 사용하지 않는다. 카드·카카오페이·휴대폰 소액결제 지원 여부는 각 승인 범위로 결정되며, 알리고 SMS 인증과 휴대폰 소액결제는 별개다.

## 살롱챗에서 먼저 정리할 화면

- 실제 운영 URL 및 사업자 정보를 확정하고 상품 설명·이용약관·개인정보처리방침·환불정책을 읽을 수 있는 페이지로 제공한다. 현재 일부 정책은 한 줄 알림창이다.
- 하트 가격/수량, 사용 방식, 유효기간 및 환불 조건을 상품 화면에서 명확히 보여준다. 정책 내용은 사업자의 결정과 PG 계약 검토가 필요하다.
- 현재 선물 화면은 가상 상품인데 실제 매장 사용·택배·기프티콘처럼 적힌 부분이 있다. 실제 제공 대상이 AI 캐릭터용 가상 선물이라면 그에 맞게 설명을 고쳐야 한다. 실물/교환권을 판매하려면 실제 발행·배송 체계가 별도로 필요하다.
- 승인된 결제수단만 노출한다. 현재 카카오페이·카드·휴대폰 버튼은 실제 연동이 없다. 카드 승인만 확인되면 우선 카드부터 연다.
- 결제는 휴대폰 인증된 고객 계정에서 시작하도록 하여 구매 내역과 하트를 그 계정에 연결한다. 주문/결제 ID는 전화번호가 드러나지 않는 무작위 식별자를 사용한다.

## 구현 흐름

1. 인증된 계정이 상품 키를 보낸다. 서버는 상품표에서 원화 금액과 지급 하트 수를 정하고 결제 전 주문을 SQLite에 저장한다. 클라이언트가 보낸 가격·지급 수량은 신뢰하지 않는다.
2. PortOne Browser SDK V2로 승인된 살롱챗 채널의 KG이니시스 결제창을 연다. 모바일 복귀 주소와 살롱챗 전용 웹훅 주소를 설정한다.
3. 브라우저 완료 요청과 웹훅 모두 하나의 서버 검증 함수를 호출한다. PortOne 결제 조회에서 결제 ID, `PAID`, KRW, 금액, 상품명, Store ID, 승인된 LIVE 채널과 주문 소유자를 대조한다. 웹훅 서명만으로 지급하지 않는다.
4. 주문 완료 전환, 유료 하트 지급, 재화 원장 기록을 하나의 SQLite 트랜잭션으로 처리한다. PG 결제 ID와 지급 기록에 고유 제약을 두어 웹훅 중복·새로고침·동시 요청에도 한 번만 지급한다.
5. 사용자가 결제 후 브라우저를 닫아도 웹훅/재조회 작업이 충전을 완료한다. 재접속하면 인증 계정의 서버 잔액을 불러온다. 결제 내역과 재확인 화면을 제공한다.
6. 취소·부분취소·환불을 PG 거래와 원장에 연동한다. 유료 하트와 무료 보너스, 주문별 잔여 하트 및 사용 내역을 구분해야 이미 쓴 하트와 환불액을 정확히 계산할 수 있다. 현재 합산 하트 잔액만으로 환불을 구현하지 않는다.

예정 엔드포인트:
- `POST /api/payment/prepare`: 회원 전용 주문 생성
- `POST /api/payment/verify`: 소유 주문의 PG 조회·검증·한 번만 지급
- `POST /api/payment/webhook`: 서명 검증과 주문 상태 재조회
- `GET /api/payment/orders`: 본인의 결제 내역
- 결제 복귀 페이지: `/payment/complete`

Express에서는 웹훅 경로에서 서명 검증용 원문 본문을 보존해야 한다. 현재 전역 `express.json()`보다 앞에 전용 raw-body 처리를 둔다. 웹훅에는 브라우저 JWT를 요구하지 않고 PG 서명을 검증한다. 다른 사람의 주문 정보나 전화번호가 응답으로 노출되지 않게 한다.

현재 `server/routes/payment.js`는 PG 조회 없이 주문을 완료시키는 데모이며, 공개 환경에서는 차단되어 있다. 부분 보완으로 활성화하지 않고 실검증 경로로 교체해야 한다.

## 실행 순서와 필요한 정보

1. 운영 URL·상품/환불/콘텐츠 정책 정리 및 살롱챗 서비스 추가 문의.
2. 기존 포트원 계정에 살롱챗용 상점/채널을 분리하고 TEST 연동 구현.
3. 결제 성공·실패·취소, 모바일 복귀, 중복 웹훅, 위조 금액, 다른 계정 접근, 재시작 후 미지급 복구를 검증.
4. PG 심사 결과에 따라 살롱챗 전용 MID/LIVE 채널 및 웹훅 Secret을 설정. API Secret의 계정/상점 적용 범위도 확인하고 최소 범위로 보관.
5. 승인된 수단에 한해 LIVE 결제를 열고 실제 결제/환불 검증은 결제 주체의 명시적 승인 아래 진행.

필요 정보: 살롱챗 운영 URL, 서비스 추가/MID 승인 내역, 살롱챗 Store ID·TEST/LIVE 채널, 서버 API Secret, 살롱챗 웹훅 Secret. 비밀값은 채팅이나 Git에 넣지 않고 기존 OCI의 전용 환경 파일로 관리한다.

## PG 문의 초안 (미발송)

> 메이비웍스는 기존 비즈사주 서비스에서 포트원 V2 / KG이니시스를 사용 중입니다. 동일 사업자로 살롱챗이라는 AI 캐릭터 1:1 대화 서비스를 추가하고자 합니다. 고객이 결제한 하트로 대화 및 가상 콘텐츠를 이용하는 구조입니다. 실제 운영 URL과 상품/환불정책 및 콘텐츠 범위를 제출하여 검토받고 싶습니다. 서비스 추가 심사와 별도 MID 발급 절차, 포인트 충전 상품의 입점 조건 및 카드/제휴 간편결제 지원 범위를 안내 부탁드립니다. 필요한 보증보험·사용기간·환불 기준도 함께 확인 부탁드립니다.

현금화·양도 여부 및 사용기간은 실제 정책을 확정한 후 문의에 추가한다. 이 문의는 자동 발송하지 않았다.

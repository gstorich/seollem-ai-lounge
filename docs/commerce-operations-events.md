# 인증·결제 운영 이벤트

관리자 메뉴 **인증·결제 이벤트**에서 문자·로그인, 본인·성인인증, 결제, 환불을 조회한다. 7/30/90일은 KST 달력일 기준이며 테스트 모드, 테스트 계정과 별칭·기기로 연결된 계정은 기본 제외한다. 필요하면 테스트 포함으로 비교한다.

## 기록의 의미

- 문자 발송/검증: 성공·실패, 입력 오류, 60초 제한/당일 제한, 문자 서비스 미설정/발송 실패. 한 요청의 발송과 검증은 가능한 경우 challenge ID로 연결한다. 인증 시작 전 입력 오류 등은 별도 요청 ID를 생성한다.
- 본인·성인인증: 요청 생성, 외부 창 호출/응답/취소/오류/리다이렉트 복귀, 기관 검증 실패, 19세 이상/미만 확인.
- 결제: 요청 생성, 외부 창 관측, 기관 조회·주문 검증 실패, 승인 대기/실패/확정/취소. 웹훅·자동 재조회도 같은 원장 경로에서 기록한다.
- 환불: 미사용 하트 보류와 결과 대기, 거절/불확실 결과, 기관 확인 후 환불 확정. 결과 재조회는 조회만 수행하며 불확실한 취소를 자동 재요청하지 않는다.

`*_ok`는 API 처리 응답이지 결제 성공/성인 확인 확정이 아니다. 브라우저 관측은 미신뢰 정보다. `paid`, `verified_adult`, `verified_under19`, `completed`만 서버의 검증 결과를 의미한다. 같은 확정 결과는 원장과 동일한 SQLite 트랜잭션에서 중복 제거한다. 단계별 발생·요청 수는 활동 집계이며 동일 코호트의 순차 전환율이 아니다.

클라이언트 전송은 로그인, 요청 소유권, 단계 허용 목록, 속도 제한을 적용하며 실패해도 사용자 결제 진행을 막지 않는다. 외부 창을 닫거나 브라우저/통신이 종료되면 클라이언트 이벤트가 누락될 수 있다. 확정 결제는 서버의 PG 조회가 기준이다. 인증되지 않은 봇 요청은 고객 이벤트로 집계하지 않는다.

## 대응

1. 확인 필요 목록에서 경과·대응을 연다. 실패 코드와 동일 요청 타임라인, 고객 상세를 확인한다.
2. 결제·환불은 **PG 결과 재조회**, 본인인증은 **인증기관 결과 재조회**를 사용한다. 인증 요청이 만료/삭제되었으면 고객이 새로 시작해야 한다.
3. 문자 실패는 설정·발송사 잔액·요청 제한을 확인하고 고객에게 직접 재인증하도록 안내한다. 운영자가 OTP를 조회하거나 대신 인증하지 않는다.
4. 고객 응대 내용을 메모하고 처리 완료로 표시한다. 이는 업무 표시이며 원장·성인 권한을 변경하지 않는다. 처리 이후 새 오류가 생기면 다시 확인 필요에 표시한다.
5. 실제 환불은 기존 **결제·환불** 메뉴에서 정책에 맞춰 명시적으로 실행한다. 결과가 불확실하면 PG 내역부터 확인한다.

새 이벤트는 배포 이후부터 기록한다. 과거 기록을 성공 이벤트로 소급 생성하지 않는다. 상세 이벤트·운영 메모는 90일 초과 시 정리하며 기존 거래·문의·감사 기록의 별도 보관 기준은 유지한다. 이벤트에는 OTP, 생년월일, CI/DI, 카드정보, 키, 공급자 응답 원문을 넣지 않는다. 정해진 코드만 저장하며 상세 이벤트를 GA/Meta에 전송하지 않는다.

## 검증

`node server/tests/commerce-events.cjs`: 확정 이벤트 중복 제거, 오류 원문 미저장, 대기/복구 분류, 테스트 계정·기기 제외, 소유권, 브라우저 성공 위조 차단, 관리자 세션/CSRF, 메모, 기관 재조회, 90일 정리.
기존 `commerce.cjs`, `inicis.cjs`, `accounts.cjs`, `operations.cjs`, 광고·법무·하트·smoke 회귀 테스트도 함께 실행한다. 실제 PG 승인/성인인증은 개통 후 별도 운영 확인이 필요하다.
